# CLI 실패 응답과 Claude 프롬프트 경계 수정

## 이슈 #81: 구조화된 실패 응답

Claude와 Codex의 동기·비동기 호출은 CLI 종료 코드가 0이 아니어도 stdout을
파싱합니다. 구조화된 오류 메시지와 CLI가 보고한 토큰 사용량을 보존합니다.
stdout에 구조화된 오류가 없으면 기존처럼 stderr 또는 `exit=<code>`를
사용합니다. 실패 응답의 content는 비우고, 실제 종료 코드와 원본 stderr는
유지합니다.

Claude의 숫자형 `api_error_status: 429`는 메시지에 한도 관련 표현이 없어도
`usage_limit`으로 분류합니다. 기존의 명시적 fallback 설정에서 이 분류를
사용할 수 있으며, 자동 재시도를 추가하지는 않습니다.

## 이슈 #82: 옵션처럼 보이는 프롬프트

Claude의 argv 프롬프트는 모든 CLI 옵션 뒤의 `--` 구분자 다음에 배치합니다.
`--version`, `--help`, `- hello bullet` 같은 입력도 프롬프트 텍스트로 전달합니다.
새 세션, 재개 세션, 두 JSON 출력 모드에 동일하게 적용합니다. 긴 프롬프트는
기존처럼 stdin으로 전달하며 EOF 처리도 유지합니다.

## 검증과 범위

`tests/test_cli_failure_contract.py`는 두 프로바이더의 동기·비동기 호출,
공개 클라이언트의 오류 정규화, stderr 대체 처리, 사용량 보존, 숫자형 429,
Claude 프롬프트 경계를 검증합니다. 기존 Claude 명령 구성 테스트도 갱신했습니다.
테스트는 CLI 응답을 모의하며 모델 사용량을 소비하지 않습니다.

2026-10-22 Windows 전체 테스트 결과는 **1,307개 통과, 39개 건너뜀**입니다.
JUnit 결과는 `output/fixes-81-82-20261022/pytest.xml`에 저장했습니다.

이번 변경에는 리셋 쿠폰 조회·사용, 공개 비용·상태 필드, 새로운 스트리밍 오류
처리를 추가하지 않습니다.
