# 보안 수정 진행 기록

[English](security-hardening.md) | [한국어](security-hardening.ko.md)

작업 브랜치: `fix/security-hardening`. 기준: 배포된 v0.7.5.
아직 새 버전으로 배포하지 않았다. 기존 v0.7.5 태그와 wheel은 변경하지 않는다.

## 1단계 — SEC-005: 자동 진단의 민감한 payload 노출

모든 인증 필드를 추측하는 대신, 진단용 argv에서 MCP/config 본문 전체를 가린다.
자동 로그에는 stderr 원문과 subprocess 예외 본문을 남기지 않는다.
trace schema 2는 stderr 길이 표시와 종료 코드·시간·호출/세션 ID·청크 타임라인을
유지한다. trace 기록 함수 자체에서도 argv/stderr를 가려 직접 호출을 보호한다.

실제 실행 argv, native 세션 처리, 도구 권한, CLI 오류, 응답 본문, 토큰 집계,
fallback 동작은 바꾸지 않는다. 런타임 의존성이나 모델 호출을 추가하지 않는다.
호스트 앱에는 오류 원문을 계속 반환하므로 앱이 표시·로깅을 통제해야 한다.
이 수정은 임의의 메타데이터나 애플리케이션 로그를 보호하는 범용 비밀값 제거기가
아니다. trace 접근은 계속 제한해야 한다. 기존 로그는 자동으로 수정하지 않으므로
접근 범위와 보관 정책을 별도로 확인한다.

회귀 테스트는 가짜 인증값과 subprocess만 사용한다. 설정 인자 마스킹, trace
기록 경계, Claude/Codex/Copilot 동기·비동기 실패, 클라이언트 실패 로그,
스트리밍 stderr와 예외 본문을 검증한다. 새 테스트는 기준 코드에서 실패하고
수정 후 통과한다.

Windows 오프라인 소규모 측정에서 argv 마스킹과 JSON 직렬화를 비교했다.
짧은 debug 기록은 기준 2.05µs, 수정 후 2.82µs였고, 32,000자 MCP 설정은
36.93µs에서 2.55µs로 줄었다. 로컬 진단 경로 측정이며 모델 지연이나 운영 성능의
보장이 아니다. debug를 끈 정상 호출에서는 이 마스킹 경로를 실행하지 않는다.

## 2단계 — SEC-003: 프로필 권한 전달

프로필의 비어 있지 않은 도구 제한과 MCP 설정을 `provider_options`에 합친다.
명시한 호출별 설정이 우선하며 프로필 객체는 변경하지 않는다. Copilot도 호출별
도구 목록을 받고 허용 목록을 지정하면 `--allow-all-tools`를 생략한다. 지원하지
않는 보안 옵션과 `provider_options`를 통한 라우팅 덮어쓰기는 대화 생성이나 CLI
실행 전에 거절한다. 일반 진단 옵션의 미지원 무시는 유지한다. 관련 테스트
126개가 통과했으며 프로필의 동기·비동기·스트리밍 경로를 검증했다.

## 3단계 — SEC-002 / SEC-008: 대화 범위

대화 ID와 생존 여부 조회에도 일치하는 `owner`를 요구한다. 다른 소유자의 문맥을
주입하려면 호스트 `context_authorizer(owner, source)`가 정확히 `True`를 반환해야
하며, 없는 문맥은 대상 대화 생성 전에 거절한다. 성공한 대화는 정규화한 작업
폴더에 바인딩된다. 다른 폴더에는 다른 alias를 사용하며 세션을 조용히 초기화하지
않는다. 바인딩 없는 기존 핸들은 첫 성공 호출에 바인딩되므로 기존 이력을 확인하거나
미확인 핸들은 새 세션으로 시작한다. Copilot native 이름은 앱 대화 ID에서 만들며
다른 소유자의 동일 alias가 계정 전역 세션을 재개하지 않게 한다. 관련 테스트는
121개 통과, 플랫폼별 6개 제외다. ID로 재개할 때도 원래 소유자를 지정한다.
