# agentcli v0.7.5

[English](https://github.com/saintiron82/agentcli/blob/v0.7.5/docs/releases/v0.7.5.md) | [한국어](https://github.com/saintiron82/agentcli/blob/v0.7.5/docs/releases/v0.7.5.ko.md)

Release date: 2026-10-12. This release packages the changes since v0.7.4:
account quota lookup, structured outputs, and compatibility fixes for modern Codex CLIs.

## Install

Install the tagged source with Git available:

```bash
python -m pip install --upgrade "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.5"
```

Or install the `agentcli_py-0.7.5-py3-none-any.whl` attached to the GitHub Release.
The wheel contains the library, not provider CLI binaries or credentials.
Python 3.11+ and separately installed/authenticated provider CLIs are required.
GitHub publication does not imply that this version is available on PyPI.

## Added

- `get_account_usage()` and `get_account_usage_async()` return normalized Claude/Codex
  subscription utilization and reset windows through `AccountUsage` and `UsageWindow`.
  Query support with `client.supports(provider, "account_usage")`.
- Claude browser OAuth and Codex ChatGPT OAuth use GET usage lookups. Claude
  setup-token inference probes require `allow_probe=True`; `max_tokens=1` caps
  output, not total consumption. Credentials are never refreshed or rewritten.
- Structured output with `output_schema`, `validator`, and `schema_retries` on
  `chat` / `chat_async`. Validated data is returned in `response.parsed`;
  exhausted validation retries return a structured schema error (issue #72).
- Paired Korean/English account usage documentation and a coordinator-loop
  cookbook example for multi-agent applications.

## Fixed

- Codex approval policy now uses `-c approval_policy=...`, not the removed
  `-a` flag (issue #74).
- `full_auto` remains accepted for compatibility but no longer emits the
  removed `--full-auto` flag, restoring compatibility with codex-cli 0.149+
  (issue #76).
- Invalid reasoning defaults fail at provider construction; empty reasoning
  strings are normalized consistently (issue #38 follow-ups).

## Release behavior and boundaries

GitHub Releases now depend on successful tests/builds, not successful PyPI
publishing. PyPI publishing is disabled unless the repository variable
`PYPI_PUBLISH_ENABLED` is `true` and the Trusted Publisher is configured.

Account quota is separate from local token statistics. Missing windows are
unknown, and successful lookup does not guarantee remaining quota. API-key
billing, Copilot/Kiro quota lookup, and keychain-only credential discovery are
not supported. Account usage regression tests use fake credentials and local
HTTP responses; they do not establish live-account endpoint availability.
