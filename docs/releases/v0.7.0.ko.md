# agentcli v0.7.0

[English](v0.7.0.md) | [한국어](v0.7.0.ko.md)

프로바이더 전반의 정규화된 reasoning 제어를 추가하고, Claude 세션 resume 을
막던 stale Windows 가드를 제거하며, 서브프로세스 경계를 강화한다(대형 프롬프트
stdin 전달, 타임아웃 출력 보존, fork 취소).

## 설치

GitHub 우선 릴리즈:

```bash
pip install "agentcli @ git+https://github.com/saintiron82/agentcli.git@v0.7.0"
```

향후 PyPI 릴리즈:

```bash
pip install agentcli-py
```

## 추가

- **정규화된 reasoning 제어.** `chat` / `chat_async` / `chat_stream` 과 각
  프로바이더에 1급 `effort`(minimal…max) 와 `thinking`(off/concise/detailed) 을
  추가했다. 프로바이더별로 매핑하되 범위를 벗어나면 clamp 후 보고한다
  (`LLMResponse.reasoning` + 스트리밍 `event` 청크). `capability_matrix()` 에
  `effort_levels` / `thinking_levels` 가 추가된다. claude 는 thinking 토글이
  없어 미지원으로 보고되고, kiro 는 범위 밖이다.
- **Claude OAuth 토큰 주입 (#36).** `ClaudeProvider` 가 별도 OAuth 토큰을
  해석해(호출 인자 > 생성자 기본값 > `AGENTCLI_CLAUDE_OAUTH_TOKEN` 환경변수 >
  `~/.agentcli/claude_oauth_token` 파일) 서브프로세스 env 에
  `CLAUDE_CODE_OAUTH_TOKEN` 으로 주입한다. `~/.claude` 를 읽기 전용으로 마운트한
  헤드리스/컨테이너 배포에서 매일 발생하던 401 을 우회한다. 토큰은 argv 나 debug
  트레이스에 절대 나타나지 않는다. 소스를 설정하지 않으면 이전과 동작이 같다.

## 변경

- **Claude 세션 resume 이 Windows 에서도 동작한다 (#27).** Windows 전용
  `supports_sessions = platform.system() != "Windows"` 가드를 제거했다.
  이 가드는 issue #4(=`claude -p` 에 `--resume` 을 붙이면 인터랙티브 입력을
  5분 이상 기다리며 hang) 때문에 들어갔지만, 진짜 방아쇠는 **인터랙티브 stdin
  대기**였고 지금은 어느 spawn 경로도 CLI 가 읽을 수 있는 stdin 을 열어두지
  않는다. 서브프로세스 헬퍼가 `stdin=DEVNULL` 을 설정하거나, 8,000 UTF-8 바이트
  초과 프롬프트는 write 후 즉시 닫는 `stdin=PIPE`(#30) 이다. 따라서 그 hang 은
  발생할 수 없고 가드는 stale 이었다.

  이 검증 과정에서 함께 강화한 것: `run_subprocess_async` 는 `input_bytes` 와
  `use_stdin_devnull` 이 둘 다 없으면 `stdin` 을 설정하지 않아 **부모 stdin 을
  상속**했다. 살아 있는 부모 stdin 을 주고 측정하니 #4 가 그대로 재현됐다
  (`timed_out=True, rc=124`) — 안전이 불변식이 아니라 호출자 규율이었던 것이다.
  이제 쓰지 않는 stdin 은 언제나 닫으므로 `run_subprocess_sync` 와 대칭이다.
  기존 동작에 의존한 프로덕션 호출부는 없다(claude/codex/copilot 모두 플래그를
  명시 전달).

  이제 `ClaudeProvider.supports_sessions` 가 전 플랫폼에서 `True` 이므로
  Windows 에서도 `owner` + `alias` 세션 재사용과 `ContextSession` 의
  pin-then-`refine` 이 동작한다 — 대용량 컨텍스트를 호출마다 재전송하지 않고
  세션에 한 번만 적재한다. 만료된 세션은 여전히 `STALE_SESSION_MARKER` 자동복구
  경로를 통해 새 세션으로 graceful fallback 한다.

  **주의할 동작 변경:** Windows 에서 같은 `owner` + `alias` 로 반복 호출하면
  이제 매번 새 대화가 아니라 하나의 대화가 이어진다. 기존의 무상태 동작에
  의존하던 코드는 호출마다 `new_session=True` 를 넘기거나 새 alias 를 써야 한다.
- **`CopilotProvider(effort=...)` 가 정규 스케일로 검증된다.** 이전(v0.2.0 이후)
  에는 어떤 문자열이든 CLI 의 `--effort` 플래그로 그대로 넘어갔다. 이제 다른
  프로바이더와 동일한 정규 스케일(`minimal`/`low`/`medium`/`high`/`xhigh`/`max`)
  로 해석하고, 정규값이 아니면 `ValueError` 를 낸다 — copilot 자체의 네이티브
  `"none"` 도 포함이다. 정규값 `"minimal"` 을 넘기면 네이티브 `none` 으로
  매핑된다.

## 수정

- **서브프로세스 타임아웃이 수집된 부분 stdout/stderr 를 더 이상 버리지 않는다
  (#34).** 타임아웃이 나면 이미 캡처한 출력을 통째로 버려서 `--debug` 트레이스로
  타임아웃 당시 상황을 진단할 수 없었다. 이제 타임아웃 전까지 모인 부분 바이트를
  보존해 debug 트레이스에 노출한다. `invoke_async` 도 sync 경로처럼 stdin 을
  닫는다.
- **대형 프롬프트가 argv 대신 stdin 으로 전달된다 (#30).** 8,000 UTF-8 바이트를
  넘는 프롬프트는 claude/codex 의 `invoke` / `invoke_async` 에서 stdin 으로
  전달되어 Windows 의 32,767자 명령행 한계를 우회한다. 범위: copilot CLI 는
  stdin 프롬프트 모드가 없어 적용할 수 없고, `stream_async` 는 모든 프로바이더에서
  여전히 argv 전용이다 — #44 에서 추적한다.
- **`ContextSession.fork_many` 의 형제 취소와 race-free 자동 라벨 (#31).** 한
  fork 가 예외를 내면 아직 실행 중이던 다른 형제 fork 들이 취소되지 않고 감독
  없이 계속 돌았다. 이제 예외를 낸 fork 가 실행 중인 형제들을 취소하고,
  `labels` 를 넘기지 않을 때 자동 생성되는 fork 라벨도 race 가 없다.

## 검증

- hermetic 테스트 스위트 통과 — 이번 릴리즈에 기인한 회귀 없음.
  `build` + `twine check` 통과.
- #27 가드 제거는 Windows 11 / Claude Code 2.1.220 에서 시나리오별 2회씩
  end-to-end 로 검증했고, 모든 실행에서 세션 연속성이 유지되고 hang 이 없었다:
  - `owner` + `alias` 일반 resume (같은 session id 유지, 호출당 6.9~11.1초)
  - 12.7 KB 프롬프트의 `stdin=PIPE` 경로 + `--resume` 조합 — 최초 #28 분석이
    다루지 않았던 유일한 미검증 조합
  - MCP-on (실제 stdio MCP 서버를 붙이고 그 도구가 실제로 호출됨) + 긴 프롬프트
    이후 resume (호출당 13.6~27.2초)
- `tests/test_issue_27.py` 가 수정의 두 축을 고정한다: 전 플랫폼에서 `--resume`
  이 방출되는지, 그리고 어느 spawn 경로도 CLI 가 읽을 수 있는 stdin 을 열어두지
  않는지.
