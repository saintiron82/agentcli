# agentcli v0.7.2

[English](v0.7.2.md) | [한국어](v0.7.2.ko.md)

Environment tiers with an isolation-first default, real claude system-prompt
flags with cache-token visibility, and two latency/robustness fixes for
data-processing workloads.

**This release changes the claude provider's default behavior** — see
*Breaking* below before upgrading.

## Install

GitHub-first release:

```bash
pip install "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.2"
```

## Breaking

- **The claude provider no longer inherits the host environment by default
  (issue #59).** What a spawned `claude` picks up from the host machine is
  now one axis, `ClaudeProvider(env=...)` (also per call via
  `provider_options`):

  | tier | what gets in | ctx tokens* | 20k-char job* |
  |---|---|---:|---:|
  | `"inherit"` | everything on the host (previous default) | 50.7k | 369.6s |
  | `"explicit"` — **new default** | only what you pass (`mcp_config`, `allowed_tools`, system prompt) + built-in tools | 31.6k | 265.4s |
  | `"isolated"` | built-in tools only; explicit MCP dead (`--safe-mode`, #56) | 29.5k | — |
  | `"lean"` | nothing — no customization, no tools | 4.8k | 145.6s |

  *Same prompts on a dev machine with 2 MCP servers + 28 skills, Claude
  Code 2.1.229; the 20k-char column is a realistic "organize this document"
  job where `inherit` sent the model into a multi-turn tool loop (592k
  cumulative context tokens).

  `explicit` rides `--setting-sources ""` + `--disable-slash-commands` +
  `--strict-mcp-config` — measured as the only isolation lever that cuts
  ambient MCP/skills inheritance while still honoring an explicit
  `--mcp-config`. Built-in names in `allowed_tools` ride `--tools` (the
  definition allowlist that actually shrinks context); a list containing
  `mcp__*` names rides `--allowedTools` so narrowing your own MCP server's
  tools keeps working. `lean=True` / `isolated=True` remain boolean aliases
  for their tiers; combining them with `env` raises `ValueError`.

  **Migration:** calls that relied on host MCP servers / skills / CLAUDE.md
  must pass `env="inherit"`. Per-call `lean=False`/`isolated=False` now
  falls back to `explicit`, not to inheritance. Known limit: `explicit`
  still loads ~1k tokens of CLAUDE.md (auto-discovery is a separate CLI
  mechanism — `isolated` cuts it).

## Added

- **Real claude system-prompt flags (issue #51).** `system_prompt=` /
  `Message(role="system")` now ride `--append-system-prompt` (or a temp
  file + `--append-system-prompt-file` over the same 8,000-byte threshold
  the prompt-stdin routing uses) instead of being flattened into the `-p`
  string — so a large static block can sit on a stable, cacheable prefix.
- **Claude cache-token visibility (issue #51).**
  `usage.cache_read_input_tokens` / `cache_creation_input_tokens` land in
  `TokenUsage.cached_tokens` / `TokenUsage.cache_creation_tokens`, so
  callers can verify whether isolating static context earns the caching
  discount. Behavior change: claude's `prompt_tokens` now reports the real
  input context (`input + cache_read + cache_creation`).
- **Host-environment isolation decoupled from lean (issue #56)** —
  subsumed by the `env` tiers above; `isolated=True` is the tier alias.

## Fixed

- **Warm sessions no longer die on long responses (issue #54).** The stdout
  pipe kept asyncio's default 64KiB line cap while the warm protocol puts a
  whole event on one line — any response event over 64KiB raised
  `ValueError: Separator is found, but chunk is longer than limit`
  regardless of request size. The limit is now 8MiB by default, tunable via
  `open_warm(stream_limit=...)`; a genuine overflow raises
  `WarmSessionError` (the documented close-and-reopen contract).
- **`stream_async` routes large prompts through stdin (issue #44)** — the
  streaming spawn path now applies the same 8,000-byte threshold as
  `invoke`, keeping large `chat_stream()` seeds under Windows' argv limit.
