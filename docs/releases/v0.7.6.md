# agentcli v0.7.6

[English](https://github.com/saintiron82/agentcli/blob/v0.7.6/docs/releases/v0.7.6.md) | [한국어](https://github.com/saintiron82/agentcli/blob/v0.7.6/docs/releases/v0.7.6.ko.md)

Release date: 2026-10-22. This release includes security hardening, independent
service authentication, session/concurrency repairs, and CLI failure fixes
developed since v0.7.5.

## Install

```bash
python -m pip install --upgrade "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.6"
```

The GitHub Release also provides `agentcli_py-0.7.6-py3-none-any.whl` and a source
archive. Python 3.11+ and separately installed/authenticated provider CLIs are
required. Runtime dependencies remain zero. GitHub publication does not imply
PyPI publication; the existing repository opt-in controls that separate path.

## Fixed

- Claude prompts are placed after all options and `--`, so `--version`, `--help`,
  and leading hyphens are passed as user text. Large prompts retain stdin/EOF
  handling (issue #82).
- Claude/Codex sync and async calls preserve structured stdout errors and
  reported usage on nonzero exits. Claude numeric HTTP 429 is classified as
  `usage_limit`; stderr and native exit codes remain available (issue #81).
- Streams close owned generators/processes on cancellation and early exit.
  Partial text followed by failure remains a failed response; error chunks retain
  session and usage information.
- Session leases survive cancellation until workers finish. In-flight and queued
  sessions are protected from eviction/reset races, and same-session operations
  coordinate across clients, modes and local SQLite processes.
- Filesystem materialization preserves user skills, rejects overlapping skill
  trees and internal links, and accepts trusted workspace root aliases on macOS.
- Codex greeting/stale-session recovery uses bounded attempts with consistent
  usage accounting. Shared wall budgets cover retries; SQLite statistics use a
  consistent snapshot without loading all usage rows.

## Added and hardened

- `AuthProfile` binds service-specific credentials and native CLI state to a
  client. Rotation/disabling affects future calls; active calls keep their
  credential snapshot. See [service authentication](https://github.com/saintiron82/agentcli/blob/v0.7.6/docs/service-auth.md).
- Conversations enforce owner/workspace boundaries. Cross-owner context needs
  host authorization; unsupported or incompatible security policies fail closed.
- Windows npm shims launch their interpreter directly, unknown wrappers are
  rejected, and automatic diagnostics omit sensitive payloads (trace schema 2).
- Kiro exposes explicit filesystem read/write controls and a default 1 MiB cap.

## Upgrade and operating boundaries

Stricter security checks can reject calls that older versions allowed. Keep the
same owner and canonical workspace, pass supported provider options, and request
`new_session=True` when changing a Codex session's execution policy. Claude's
default `env="explicit"` cannot fall back to a different native provider without
an equivalent policy, even with `fallback=True`.

Authentication profiles are opt-in; existing clients keep shared authentication
until migrated. Kiro profile authentication is unsupported. `owner` is not
authentication, and profiles do not isolate hostile code under one OS user.
Multi-server writers still need host coordination. Tool side effects are not
rolled back, and cleanup/lease waiting can exceed the execution budget.

Account quota lookup remains separate from local usage statistics. This release
does not add reset-coupon lookup/redemption or public cost/HTTP-status fields.
Offline regression tests do not certify live credentials or provider endpoints.
See the [operating runbook](https://github.com/saintiron82/agentcli/blob/v0.7.6/docs/operations.md)
for rollout checks.
