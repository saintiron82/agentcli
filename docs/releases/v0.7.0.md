# agentcli v0.7.0

[English](v0.7.0.md) | [한국어](v0.7.0.ko.md)

Adds normalized reasoning controls across providers, drops the stale Windows
guard that blocked Claude session resume, and hardens the subprocess boundary
(large prompts via stdin, timeout output retention, fork cancellation).

## Install

GitHub-first release:

```bash
pip install "agentcli @ git+https://github.com/saintiron82/agentcli.git@v0.7.0"
```

Future PyPI release:

```bash
pip install agentcli-py
```

## Added

- **Normalized reasoning controls.** First-class `effort` (minimal…max) and
  `thinking` (off/concise/detailed) on `chat` / `chat_async` / `chat_stream` and
  on each provider, mapped per provider with clamp-and-report
  (`LLMResponse.reasoning` plus a streaming `event` chunk). `capability_matrix()`
  gains `effort_levels` / `thinking_levels`. claude has no thinking toggle (so it
  is reported unsupported); kiro is out of scope.
- **Claude OAuth token injection (#36).** `ClaudeProvider` resolves a separate
  OAuth token (per-call kwarg > constructor default > `AGENTCLI_CLAUDE_OAUTH_TOKEN`
  env var > `~/.agentcli/claude_oauth_token` file) and injects it as
  `CLAUDE_CODE_OAUTH_TOKEN` into the subprocess env, so headless/container
  deployments with a read-only `~/.claude` mount stop hitting daily 401s. The
  token never appears in argv or debug traces. With no source configured,
  behavior is identical to before.

## Changed

- **Claude session resume now works on Windows too (#27).** The Windows-only
  `supports_sessions = platform.system() != "Windows"` guard is removed.
  It was added for the issue #4 hang, where `claude -p` combined with `--resume`
  waited on interactive input for 5+ minutes — but the trigger was the
  **interactive stdin wait**, and no spawn path leaves stdin open for the CLI to
  read from: the subprocess helpers set `stdin=DEVNULL`, or `stdin=PIPE`
  written and closed for prompts over 8,000 UTF-8 bytes (#30). So the hang
  cannot occur and the guard was stale.

  Hardened while verifying this: `run_subprocess_async` used to leave `stdin`
  unset when given neither `input_bytes` nor `use_stdin_devnull`, so the child
  inherited the parent's stdin. Measured against a live parent stdin that
  reproduced #4 exactly (`timed_out=True, rc=124`) — safety was caller
  discipline, not an invariant. The helper now always closes stdin it does not
  write to, matching `run_subprocess_sync`. No production caller relied on the
  old behavior (claude/codex/copilot all passed the flag explicitly).

  `ClaudeProvider.supports_sessions` is now `True` on every platform, which
  makes `owner` + `alias` session reuse and `ContextSession` pin-then-`refine`
  work on Windows — a large context is seeded once instead of being re-sent on
  every call. Stale sessions still fall back to a fresh session through the
  `STALE_SESSION_MARKER` auto-recovery path.

  **Behavior change to be aware of:** on Windows, repeated calls with the same
  `owner` + `alias` now continue one conversation instead of starting a fresh
  one each time. Code that relied on the old stateless behavior should pass
  `new_session=True` (or use a new alias) per call.
- **`CopilotProvider(effort=...)` now validates against the canonical scale.**
  Previously (since v0.2.0) any string was passed straight through to the CLI's
  `--effort` flag. It now resolves through the same canonical scale as the other
  providers (`minimal`/`low`/`medium`/`high`/`xhigh`/`max`) and raises
  `ValueError` for a non-canonical string — including copilot's own native
  `"none"`; pass canonical `"minimal"`, which maps to native `none`.

## Fixed

- **Subprocess timeout no longer discards collected partial stdout/stderr (#34).**
  A timeout used to drop whatever output had already been captured, which made
  `--debug` traces useless for diagnosing what a timed-out call was doing. The
  partial bytes are now preserved and surfaced in the debug trace; `invoke_async`
  also closes stdin like the sync path already did.
- **Large prompts now route through stdin instead of argv (#30).** Prompts over
  8,000 UTF-8 bytes are passed via stdin for claude/codex `invoke` /
  `invoke_async`, avoiding the Windows 32,767-character argv limit. Scope: the
  copilot CLI has no stdin prompt mode, so this cannot apply there, and
  `stream_async` remains argv-only for all providers — tracked in #44.
- **`ContextSession.fork_many` sibling cancellation and race-free auto-labels
  (#31).** When one fork raised, the other still-running sibling forks used to
  keep running unsupervised instead of being cancelled. A raising fork now
  cancels its still-running siblings, and auto-generated fork labels (used when
  `labels` isn't passed) are race-free.

## Verification

- Hermetic test suite passes with no regressions attributable to this release;
  `build` + `twine check` pass.
- The #27 guard removal was verified end-to-end on Windows 11 against Claude
  Code 2.1.220, twice per scenario, with session continuity confirmed and no
  hang in any run:
  - plain resume via `owner` + `alias` (same session id retained; 6.9–11.1s per call)
  - a 12.7 KB prompt on the `stdin=PIPE` path combined with `--resume`, which is
    the one combination the original #28 analysis had not covered
  - MCP-on (a real stdio MCP server attached, its tool actually invoked) with a
    long prompt, then resumed (13.6–27.2s per call)
- `tests/test_issue_27.py` pins both halves of the fix: that `--resume` is
  emitted on every platform, and that neither spawn path leaves stdin open for
  the CLI to read from.
