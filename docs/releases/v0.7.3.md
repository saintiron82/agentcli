# agentcli v0.7.3

[English](v0.7.3.md) | [한국어](v0.7.3.ko.md)

Spawn-time speedups verified by measurement, and a detailed performance
guide so embedders can reason about where their latency actually goes.

## Install

GitHub-first release:

```bash
pip install "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.3"
```

## Added

- **Nonessential-traffic cutoff on every spawn (issue #62).** Every claude
  child process (invoke / streaming / warm) now gets
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` — update checks, telemetry,
  error reporting and release-note fetches are skipped at boot. Measured:
  **3.0–3.1s → 2.0s** per lean call. The host's interactive `claude` is
  unaffected (the variable rides only the child env); an explicit
  parent/caller value always wins, so setting the variable yourself (any
  value) opts out.

- **Cache-stable prompt prefix, opt-in (issue #62).**
  `ClaudeProvider(exclude_dynamic_system_prompt=True)` — also per call and
  via `provider_options` — appends `--exclude-dynamic-system-prompt-sections`.
  The CLI's system prompt embeds dynamic sections (cwd, OS info, git
  branch/status/recent commits, auto-memory paths); any commit or file
  change between calls shifts those bytes and busts the server-side prompt
  cache for everything after them, **including your `system_prompt` block**
  (#51). With the flag, those sections move into the first user message and
  the prefix stays byte-stable. Measured across an interposed git change:
  `cache_creation` **1693 → 519**, `cache_read` **3289 → 4219** per call —
  the bigger your static system prompt, the bigger the win. Opt-in because
  older CLIs without the flag fail with unknown-option (verified on
  2.1.229).

- **Performance guide (README, en/ko).** A detailed map of where `-p` call
  time goes and which lever cuts which part:
  - tier selection by workload (data pipelines → `lean`; tool agents →
    `explicit`; host-integrated tooling → `inherit`), with the measured
    20k-char job table (369.6s / 265.4s / 145.6s);
  - prompt-caching prefix rules — model **and effort are part of the cache
    key** (pin them per batch), subscription auth gets a 1-hour TTL,
    same-directory parallel sessions share the cache (warm one call first);
  - the quality-first rule: effort/thinking changes output quality — never
    lower it on quality-sensitive work without an A/B on your own task;
  - concurrency guidance (~3–4 simultaneous spawns before 429s, per
    community reports);
  - known upstream issues: claude-code#83859 (v2.1.220/221 headless `-p`
    can stall ~405s — keep timeouts ≥ 420s or upgrade the CLI) and
    claude-code#5653 (`~/.claude.json` bloat slows startup).

## Notes

- Verified live: default lean ping wall 3.0–3.1s → 2.0s with the traffic
  cutoff; the cache measurements above via `TokenUsage.cached_tokens` /
  `cache_creation_tokens` introduced in 0.7.2.
- Investigated and rejected: `--bare` (never reads OAuth/keychain, so it
  cannot serve subscription auth) and the Agent SDK as a transport (spawns
  the same CLI binary — no structural advantage; third-party subscription
  OAuth use is also policy-restricted).
