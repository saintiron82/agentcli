# agentcli v0.7.2

[English](v0.7.2.md) | [한국어](v0.7.2.ko.md)

격리 우선 기본값의 환경 티어, 실제 claude 시스템 프롬프트 플래그 + 캐시 토큰
가시성, 그리고 데이터 처리 워크로드용 지연/견고성 수정 2건.

**이 릴리스는 claude provider 의 기본 동작을 바꾼다** — 업그레이드 전에 아래
*Breaking* 을 볼 것.

## 설치

GitHub 우선 릴리스:

```bash
pip install "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.2"
```

## Breaking

- **claude provider 가 더 이상 호스트 환경을 기본으로 상속하지 않는다
  (issue #59).** spawn 된 `claude` 가 호스트 머신에서 무엇을 들고 들어갈지는
  이제 `ClaudeProvider(env=...)` 한 축이다(호출 시점 `provider_options` 로도
  가능):

  | 티어 | 들어가는 것 | ctx 토큰* | 2만자 작업* |
  |---|---|---:|---:|
  | `"inherit"` | 호스트의 전부 (이전 기본) | 50.7k | 369.6초 |
  | `"explicit"` — **새 기본** | 지정한 것만 (`mcp_config`, `allowed_tools`, 시스템 프롬프트) + 빌트인 툴 | 31.6k | 265.4초 |
  | `"isolated"` | 빌트인 툴만; 명시 MCP 죽음 (`--safe-mode`, #56) | 29.5k | — |
  | `"lean"` | 없음 — 커스터마이즈도 툴도 없음 | 4.8k | 145.6초 |

  *MCP 서버 2개 + skill 28개 깔린 개발 머신, Claude Code 2.1.229. 2만자
  열은 실제 "문서 정리" 작업으로, `inherit` 는 모델이 멀티턴 툴 루프에
  빠졌다(누적 컨텍스트 592k 토큰).

  `explicit` 은 `--setting-sources ""` + `--disable-slash-commands` +
  `--strict-mcp-config` 로 구현된다 — ambient MCP/스킬 상속을 끊으면서
  명시적 `--mcp-config` 는 존중하는 유일한 격리 수단으로 실측됐다.
  `allowed_tools` 의 빌트인 이름은 `--tools`(컨텍스트를 실제로 줄이는 정의
  allowlist)로, `mcp__*` 이름이 섞이면 `--allowedTools` 로 가서 자기 MCP
  서버의 툴 좁히기 패턴이 계속 동작한다. `lean=True` / `isolated=True` 는
  해당 티어의 부울 별칭으로 유지되며, `env` 와 동시 지정은 `ValueError`.

  **마이그레이션:** 호스트 MCP 서버/skills/CLAUDE.md 에 의존하던 호출은
  `env="inherit"` 를 명시한다. 호출 시점 `lean=False`/`isolated=False` 는
  이제 상속이 아니라 `explicit` 으로 떨어진다. 알려진 한계: `explicit` 은
  CLAUDE.md ~1k 토큰이 여전히 실린다(auto-discovery 는 별개 메커니즘 —
  `isolated` 는 끊는다).

## Added

- **실제 claude 시스템 프롬프트 플래그 (issue #51).** `system_prompt=` /
  `Message(role="system")` 이 `-p` 문자열로 평탄화되는 대신
  `--append-system-prompt`(8,000바이트 초과 시 임시 파일 +
  `--append-system-prompt-file`)를 탄다 — 큰 정적 블록이 캐시 가능한 안정
  접두어에 앉을 수 있다.
- **claude 캐시 토큰 가시성 (issue #51).**
  `usage.cache_read_input_tokens` / `cache_creation_input_tokens` 가
  `TokenUsage.cached_tokens` / `TokenUsage.cache_creation_tokens` 로
  들어와, 정적 컨텍스트 분리가 캐싱 할인을 실제로 받는지 확인할 수 있다.
  동작 변화: claude 의 `prompt_tokens` 는 이제 실제 입력 컨텍스트
  (`input + cache_read + cache_creation`)를 보고한다.
- **환경 격리를 lean 에서 분리 (issue #56)** — 위 `env` 티어로 흡수;
  `isolated=True` 는 티어 별칭이다.

## Fixed

- **warm 세션이 긴 응답에서 죽지 않는다 (issue #54).** stdout 파이프가
  asyncio 기본 64KiB 줄 한도를 유지하는데 warm 프로토콜은 이벤트 하나가 한
  줄이라, 64KiB 를 넘는 응답 이벤트가 요청 크기와 무관하게 `ValueError:
  Separator is found, but chunk is longer than limit` 로 터졌다. 한도는
  기본 8MiB(`open_warm(stream_limit=...)` 로 조정)이고, 정말 넘으면
  `WarmSessionError`(문서화된 닫고-다시-연다 계약)로 올라온다.
- **`stream_async` 도 큰 프롬프트를 stdin 으로 보낸다 (issue #44)** —
  스트리밍 spawn 경로가 `invoke` 와 같은 8,000바이트 임계값을 적용해 큰
  `chat_stream()` 시드가 Windows argv 한도를 넘지 않는다.
