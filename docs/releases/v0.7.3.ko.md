# agentcli v0.7.3

[English](v0.7.3.md) | [한국어](v0.7.3.ko.md)

실측으로 검증된 spawn 고속화 2건과, 임베더가 지연이 실제로 어디서 나는지
추론할 수 있게 하는 상세 성능 가이드.

## 설치

GitHub 우선 릴리스:

```bash
pip install "agentcli-py @ git+https://github.com/saintiron82/agentcli.git@v0.7.3"
```

## Added

- **모든 spawn 에 비필수 트래픽 차단 (issue #62).** 모든 claude 자식
  프로세스(invoke / 스트리밍 / warm)가
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 을 받는다 — 업데이트 체크/
  텔레메트리/에러 리포팅/릴리스노트 페치가 부팅에서 빠진다. 실측: lean 1회
  호출 **3.0–3.1초 → 2.0초**. 호스트의 대화형 `claude` 는 영향받지 않고
  (이 var 는 자식 env 에만 실린다), 부모/호출자의 명시 값이 항상 이기므로
  변수를 직접 설정하면(값 무관) 옵트아웃이다.

- **캐시 안정 프리픽스, 옵트인 (issue #62).**
  `ClaudeProvider(exclude_dynamic_system_prompt=True)` — 호출 시점·
  `provider_options` 로도 가능 — 이
  `--exclude-dynamic-system-prompt-sections` 를 붙인다. CLI 시스템
  프롬프트에는 동적 섹션(cwd, OS 정보, git 브랜치/상태/최근 커밋,
  auto-memory 경로)이 임베드되어, 호출 사이의 커밋·파일 변경이 그 바이트를
  흔들면 그 뒤 전부 — **`system_prompt` 블록(#51) 포함** — 서버측 프롬프트
  캐시가 미스된다. 플래그를 켜면 동적 섹션이 첫 user 메시지로 이동해
  프리픽스가 바이트 단위로 안정된다. git 변경을 사이에 넣은 실측: 호출당
  `cache_creation` **1693 → 519**, `cache_read` **3289 → 4219** — 정적
  시스템 프롬프트가 클수록 이득이 커진다. 옵트인인 이유: 플래그 없는
  구버전 CLI 는 unknown-option 으로 실패한다(2.1.229 검증).

- **성능 가이드 (README, 한/영).** `-p` 호출 시간이 어디로 가고 어떤
  레버가 어느 부분을 줄이는지의 상세 지도:
  - 워크로드별 티어 선택(데이터 파이프라인 → `lean`; 툴 에이전트 →
    `explicit`; 호스트 통합 도구 → `inherit`)과 2만자 작업 실측 표
    (369.6초 / 265.4초 / 145.6초);
  - 프롬프트 캐싱 프리픽스 규칙 — **모델과 effort 가 캐시 키의 일부**
    (배치 단위 고정), 구독 인증 1시간 TTL, 같은 디렉토리 병렬 세션의
    캐시 공유(한 호출 먼저 완주로 워밍);
  - 품질 우선 규칙: effort/thinking 은 출력 품질을 바꾼다 — 품질 민감
    작업에서는 자기 작업 기준 A/B 없이 낮추지 말 것;
  - 동시성 가이드(커뮤니티 보고 기준 동시 spawn ~3–4개 초과 시 429);
  - 알려진 업스트림 이슈: claude-code#83859(v2.1.220/221 headless `-p`
    ~405초 스톨 — 타임아웃 420초 이상 또는 CLI 업그레이드),
    claude-code#5653(`~/.claude.json` 비대화로 시작 지연).
